06 · single-stream speed

Per-token decode latency at batch 1

  • TP=2 costs nothing at batch 1 despite ~176 NCCL collectives per step: CUDA graphs hide the launch latency.
  • PP=2 is 1.75× slower: stages run one after another with a single request.
  • NVFP4 (weight-only FP4) decodes as fast as FP8: at batch 1 the GPU is reading weights, not computing.
07 · prefill

Why time-to-first-token is slow

  • Linear in prompt length, so it is not attention. The GPU is busy, so it is not CPU launch overhead.
  • Two thirds is the expert matmul running at ~17 % of peak: 512 experts of 1024×2688 each see ~176 rows per 4k prompt.
  • TP=2 does not help prefill (499 vs 535 ms): it halves each expert's width and makes the GEMMs smaller still.
  • Fix found: Humming MoE backend, −25 % TTFT at 4k and 8k with identical decode.

12 · round 2 · scale ceilings

Three-GPU layouts pushed to 384–768 streams

One experiment at a time, per-level seeds. Sequence lengths as in round 1; concurrency up to 768.

  • FP8 DP=3 + EP=3 leads at both lengths: 3.2k tok/s at 1k (384 streams, still rising) and 1.56k at 4k; experts sharded three ways leave 25 GiB of cache per GPU.
  • FP8 PP=3 plateaus at 2.4k (1k) and 1.4k (4k) by 512 streams; beyond that only queueing grows.
  • NVFP4 DP=3 + EP=3 reaches 2.9k at 1k but trails at 4k (1.27k): its Humming prefill is slower per token than FP8 CUTLASS.
  • Round 1 ranked DP+EP last because it was capped at 16 streams per rank; a layout's rank depends on the limits you give it.

11 · open questions

Round 1 closed; what round 2 should settle

  • Realistic traffic: Poisson arrivals, length distributions, multi-turn, and reasoning-on outputs (1k–8k tokens) instead of fixed 1k/256 random prompts — profiles in notes/06.
  • DP + EP at scale: the DP=3+EP=3 run was capped at 16 streams per rank; its 42 GiB cache per GPU should allow hundreds, where replicas stop at 48.
  • MTP with 1–2 draft tokens on real prompts: acceptance was 13 % on random text and the speedup 2.25× on greedy code; the useful operating point is in between.
  • Unquantized reference: BF16 does not fit; a CPU-offloaded run (498 GB host RAM, PCIe-bound) is the only way to measure FP8/NVFP4 quality loss locally.
  • Prefix caching: the Mamba "align" mode makes the cache block 8,320 tokens, so prompts under ~8k never hit the cache on this model; test a shared prefix ≥ 8,320 tokens.
  • Host sensitivity: PP needs an idle host, TP does not; round 2 runs one experiment at a time.
